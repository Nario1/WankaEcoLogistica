## 3. Nivel 3: Diagrama de Componentes

Este diagrama detalla la estructuración interna de los módulos que componen el contenedor principal de la API Backend (Node.js / Express). Se evidencia una arquitectura por capas limpias, separando las interfaces de red, la lógica algorítmica y el acceso a datos.

```mermaid
graph TD
    subgraph backend["Contenedor API Backend - Node.js / Express"]
        Router["Controladores / Endpoints"]
        Sec["Middleware de Seguridad y Auth"]
        SvcRuteo["Servicio de Optimización y Ruteo"]
        SvcNegocio["Servicios Transaccionales Core"]
        Repo["Capa de Repositorios / ORM"]

        Router -->|"Intercepta petición para validar"| Sec
        Sec -->|"Retorna Token Válido"| Router
        Router -->|"Delega el cálculo matemático"| SvcRuteo
        Router -->|"Delega lógica de negocio - CRUD"| SvcNegocio
        SvcRuteo -->|"Requiere coordenadas y grafos"| Repo
        SvcNegocio -->|"Persiste entidades"| Repo
    end

    WA["SPA - React"] -->|"Peticiones HTTP"| Router
    Repo -->|"Ejecuta Queries"| DB[(PostgreSQL)]
```

## 4. Estado de implementación — Sprint 1

La implementación actual materializa la SPA React/Vite, la API Express y PostgreSQL/PostGIS. La API se organiza en rutas HTTP, middleware JWT/RBAC, servicios de dominio y repositorios PostgreSQL; no se usa ORM. El frontend consume JSON mediante `fetch`, conserva la sesión en `sessionStorage` y redirige al login cuando el token vence.

Redis, OAuth2 externo, SMTP, proveedor de mapas y motor de optimización no están conectados en el Sprint 1. Deben considerarse integraciones futuras, no dependencias activas del despliegue local.
