## 1. Evaluación Rigurosa de Alternativas

Para garantizar el cumplimiento de los Requisitos Funcionales y No Funcionales, el equipo evaluó tres arquitecturas tecnológicas, utilizando criterios multidimensionales enfocados en escalabilidad, procesamiento de datos geoespaciales y sostenibilidad energética.

| Criterio de Evaluación | Alternativa 1: MERN (Node/Express + React + MongoDB) | Alternativa 2: Python / FastAPI + React + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
|---|---|---|---|
| **Curva de Aprendizaje** | Baja (JavaScript unificado) | Media (Python backend, JS frontend) | Alta (Verboso, fuertemente tipado) |
| **Costo de Infraestructura** | Moderado (Node async I/O) | Bajo (FastAPI asíncrono, bajo consumo RAM) | Alto (Mayor consumo de memoria JVM) |
| **Soporte Comunitario** | Masivo / Muy Alto | Alto / Crecimiento acelerado | Masivo / Corporativo consolidado |
| **Eficiencia Energética / Eco-Design** | Media | Alta (Métricas de cómputo eficientes) | Media-Baja (Warm-up JVM prolongado) |
| **Capacidad para Ruteo y Geo-Data** | Limitada (Carece de librerías nativas avanzadas de optimización) | Excelente (Ecosistema robusto: PostGIS y OR-Tools) | Excelente (Hibernate Spatial, sólido pero pesado) |

---

## 2. Justificación Técnica Formal

Tras un riguroso análisis comparativo, el equipo de desarrollo declara formalmente la selección de la **Alternativa 2 (Python / FastAPI + React + PostgreSQL)** como el stack tecnológico base para **WankaEcoLogística Huancayo**.

Esta decisión se sustenta en tres pilares fundamentales que alinean la tecnología con la visión y los escenarios de calidad del proyecto:

1.  **Alineación con el Eco-Design y Eficiencia Energética (Green Computing):** El framework asíncrono FastAPI permite una altísima concurrencia de peticiones consumiendo una fracción del uso de CPU y memoria RAM (en comparación con alternativas basadas en JVM). Este bajo overhead reduce directamente el consumo eléctrico del servidor en la nube, cumpliendo con el espíritu ecológico de la plataforma.
2.  **Dominio en Escalabilidad Algorítmica y Geoespacial:** Dado que el corazón del sistema (RF-004) requiere resolver problemas de enrutamiento de vehículos (VRP), Python ofrece acceso directo a las librerías matemáticas más maduras de la industria (ej. Google OR-Tools). Asimismo, PostgreSQL mediante su extensión nativa **PostGIS** garantiza la precisión espacial exigida (RNF-007) al calcular coordenadas, intersecciones y distancias reales de la ciudad.
3.  **Perfil del Equipo y Productividad:** La combinación de la sintaxis limpia de Python para la lógica algorítmica y la reactividad de React para el frontend (necesario para el mapa dinámico y las PWAs de los conductores), ofrece el balance perfecto entre desarrollo acelerado, mantenibilidad (RNF-005) y rendimiento.
