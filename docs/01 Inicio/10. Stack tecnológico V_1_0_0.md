## 1. Evaluación Rigurosa de Alternativas

Para garantizar el cumplimiento de los Requisitos Funcionales y No Funcionales, el equipo evaluó tres arquitecturas tecnológicas, utilizando criterios multidimensionales enfocados en escalabilidad, procesamiento de datos geoespaciales y sostenibilidad energética.

| Criterio de Evaluación | Alternativa 1: Node.js / Express + React + PostgreSQL | Alternativa 2: Python / FastAPI + React + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
|---|---|---|---|
| **Curva de Aprendizaje** | Baja (JavaScript unificado full-stack) | Media (Python backend, JS frontend) | Alta (Verboso, fuertemente tipado) |
| **Costo de Infraestructura** | Bajo (event-loop no bloqueante, bajo consumo RAM) | Bajo (FastAPI asíncrono, bajo consumo RAM) | Alto (Mayor consumo de memoria JVM) |
| **Soporte Comunitario** | Masivo / Ecosistema npm líder mundial | Alto / Crecimiento acelerado | Masivo / Corporativo consolidado |
| **Eficiencia Energética / Eco-Design** | Alta (Event-driven I/O, bajo overhead) | Alta (Métricas de cómputo eficientes) | Media-Baja (Warm-up JVM prolongado) |
| **Capacidad para Ruteo y Geo-Data** | Buena (node-postgres, PostGIS, librerías npm) | Excelente (Ecosistema robusto: PostGIS y OR-Tools) | Excelente (Hibernate Spatial, sólido pero pesado) |

## 2. Justificación Técnica Formal

Tras un riguroso análisis comparativo, el equipo de desarrollo declara formalmente la selección de la **Alternativa 1 (Node.js / Express + React + PostgreSQL)** como el stack tecnológico base para **WankaEcoLogística Huancayo**.

Esta decisión se sustenta en tres pilares fundamentales que alinean la tecnología con la visión y los escenarios de calidad del proyecto:

1.  **JavaScript Unificado Full-Stack y Productividad del Equipo:** Al utilizar Node.js en el backend y React en el frontend, el equipo trabaja en un único lenguaje a lo largo de todo el stack. Esto elimina el cambio de contexto cognitivo entre lenguajes, acelera el desarrollo y facilita el mantenimiento a largo plazo (RNF-005), dado que el mismo desarrollador puede contribuir en ambas capas sin fricción.
2.  **Eficiencia Energética y Eco-Design (Green Computing):** El modelo de ejecución de Node.js basado en un event-loop no bloqueante y arquitectura I/O asíncrona permite manejar una alta concurrencia de peticiones con un consumo mínimo de CPU y memoria RAM. Este bajo overhead reduce directamente el consumo eléctrico del servidor en la nube, alineándose con el espíritu ecológico y sostenible de la plataforma.
3.  **Ecosistema Maduro para Geo-Data y Escalabilidad:** El ecosistema npm ofrece librerías robustas para integraciones geoespaciales (ej. `node-postgres`, `pg-promise` con soporte PostGIS). PostgreSQL mediante su extensión **PostGIS** garantiza la precisión espacial exigida (RNF-007) al calcular coordenadas, intersecciones y distancias reales en la ciudad de Huancayo.

## 3. Estado de implementación — Sprint 1

La selección se materializó con React 19, Vite 8 y Material UI 9 en el frontend; Node.js, Express 5, `pg`, `jsonwebtoken` y `bcryptjs` en el backend; y PostgreSQL con PostGIS para la persistencia geoespacial. ESLint, Prettier y el test runner de Node se usan como herramientas de calidad.

Redis y Google OR-Tools no forman parte de la implementación actual. Desde el Sprint 03 el sistema incluye adaptador de mapas (OSRM/TomTom), vista del conductor y una base PWA offline. La fuente de dependencias vigentes es `frontend/package.json` y `backend/package.json`. La evaluación de calidad de ese incremento está en [Calidad de código](<../03 Implementación/Sprint 03/03 Calidad de código V_1_0_0.md>).
