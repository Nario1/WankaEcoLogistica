## 1. Marco de Elicitación Holística y Ética

El proceso de elicitación de requisitos para **WankaEcoLogística Huancayo** se ha diseñado bajo un enfoque integral que garantiza la representatividad, pertinencia y responsabilidad social de la plataforma:

- **Grupos de Usuarios Diversos:** Se han considerado las perspectivas de administradores de flota, conductores con distintos niveles de experiencia tecnológica, planificadores operativos y clientes finales, asegurando que las interfaces y flujos de trabajo sean accesibles y usables para todos.
- **Contexto Glocal (Global y Local):** Los requisitos integran algoritmos de enrutamiento globales aplicados a la realidad local de Huancayo (condiciones climáticas, topografía, horarios de tráfico y crecimiento comercial de la sierra central peruana).
- **Perspectiva Ética y de Sostenibilidad:** Las necesidades recabadas no solo buscan la rentabilidad empresarial, sino la reducción medible de emisiones de CO₂, el bienestar de los conductores al evitar rutas sobrecargadas, y la protección de datos personales de todos los actores involucrados.

## 2. Especificación Atómica de Requisitos Funcionales

A continuación se detalla el catálogo de requisitos funcionales del sistema, redactados de forma atómica y sin ambigüedades, siguiendo las necesidades principales de la plataforma.

### 2.1. RF-001: Gestión de Pedidos

- **Descripción Atómica:** El sistema debe almacenar y actualizar la información de un pedido (dirección, coordenadas geográficas, peso, prioridad y ventana de tiempo) cuando un operador autorizado registra o modifica los datos a través del formulario correspondiente.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un operador con sesión iniciada y permisos de gestión
CUANDO el usuario registra un nuevo pedido llenando todos los campos obligatorios con formatos válidos
ENTONCES el sistema procesa la solicitud, guarda el pedido en la base de datos y confirma la transacción correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un pedido previamente registrado que requiere actualización
CUANDO el usuario opta por modificar la ventana de tiempo del pedido
ENTONCES el sistema completa la actualización de los datos satisfaciendo el objetivo de reflejar los nuevos horarios.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un formulario de registro de pedido
CUANDO el usuario ingresa coordenadas fuera del rango permitido o un peso negativo
ENTONCES el sistema deniega la acción, mantiene el estado consistente y despliega un mensaje de error explícito indicando los campos inválidos.

---

### 2.2. RF-002: Gestión de Vehículos y Flota

- **Descripción Atómica:** El sistema debe persistir las características operativas y ambientales de un vehículo (capacidad, consumo por kilómetro y factores de emisión) cuando el administrador confirma la creación o edición del recurso móvil.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un administrador autenticado
CUANDO el usuario registra un vehículo indicando su placa, capacidad de carga máxima y métricas de consumo
ENTONCES el sistema procesa la información y confirma la creación del vehículo correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un vehículo inactivo por mantenimiento
CUANDO el usuario opta por cambiar el estado del vehículo a "Fuera de servicio"
ENTONCES el sistema completa la operación excluyendo temporalmente al vehículo de las asignaciones de ruta.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO el registro de un nuevo vehículo
CUANDO el usuario ingresa una placa que ya se encuentra registrada en el sistema
ENTONCES el sistema deniega la acción, mantiene el estado consistente y despliega un mensaje de error explícito sobre duplicidad de datos.

---

### 2.3. RF-003: Gestión de Conductores y Asignación

- **Descripción Atómica:** El sistema debe registrar conductores y asociarlos a rutas específicas cuando el planificador logístico confirma la vinculación respetando las reglas de disponibilidad.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un planificador logístico autenticado
CUANDO el usuario asigna un conductor disponible a una ruta generada
ENTONCES el sistema procesa la solicitud, vincula al conductor con la ruta y confirma la transacción correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un cambio de turno inesperado
CUANDO el usuario opta por reasignar la ruta a un conductor de respaldo
ENTONCES el sistema completa la operación satisfaciendo el objetivo operativo.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO el proceso de asignación manual
CUANDO el usuario intenta asignar un conductor que ya se encuentra en ruta en el mismo horario
ENTONCES el sistema deniega la acción, mantiene el estado consistente y despliega un mensaje de error explícito indicando conflicto de disponibilidad.

---

### 2.4. RF-004: Motor de Optimización de Rutas

- **Descripción Atómica:** El sistema debe calcular la secuencia óptima de paradas cuando el usuario solicita la generación de ruta en función a la distancia, tiempo, ventanas de entrega y congestión.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un conjunto de pedidos aprobados, vehículos disponibles y un planificador autenticado
CUANDO el usuario solicita calcular las rutas para la jornada
ENTONCES el sistema procesa las variables y genera secuencias de entrega que minimizan la distancia calculada respetando las capacidades y horarios correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un lote de pedidos con flexibilidad horaria
CUANDO el usuario opta por calcular una ruta priorizando exclusivamente el menor consumo de combustible
ENTONCES el sistema completa la operación satisfaciendo el objetivo ecológico por encima del tiempo de entrega.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un intento de optimización
CUANDO el sistema identifica que el volumen de pedidos supera la capacidad máxima de toda la flota disponible
ENTONCES el sistema deniega la generación completa, mantiene el estado consistente y despliega un mensaje de error explícito requiriendo asignar más vehículos o postergar entregas.

---

### 2.5. RF-005: Visualización Interactiva en Mapa

- **Descripción Atómica:** El sistema debe renderizar el trazado de rutas óptimas y los puntos de entrega en una interfaz cartográfica cuando un usuario con permisos de visualización accede al módulo de seguimiento.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un usuario autorizado con sesión activa
CUANDO el usuario ingresa a la vista de mapa de una ruta asignada
ENTONCES el sistema procesa las coordenadas y muestra el polilínea del trayecto sobre el mapa base correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un mapa interactivo cargado
CUANDO el usuario opta por hacer clic en un pin de entrega específico
ENTONCES el sistema completa la operación satisfaciendo el objetivo de mostrar el detalle rápido del pedido.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO el módulo de mapa
CUANDO se interrumpe la conexión con el proveedor externo de mapas
ENTONCES el sistema deniega el renderizado, mantiene el estado consistente y despliega un mensaje de error explícito de conectividad inestable.

---

### 2.6. RF-006: Dashboard de Indicadores de Sostenibilidad y Ahorro

- **Descripción Atómica:** El sistema debe calcular y mostrar métricas consolidadas (reducción de CO₂, ahorro de distancia y nivel de servicio) cuando el administrador solicita el resumen general de la operación.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un administrador consultando el panel principal
CUANDO el usuario selecciona un rango de fechas con datos operativos procesados
ENTONCES el sistema procesa el cálculo y confirma la transacción correctamente presentando los gráficos e indicadores estadísticos.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO el dashboard en pantalla
CUANDO el usuario opta por filtrar la vista para observar únicamente el indicador de emisiones
ENTONCES el sistema completa la actualización de la interfaz satisfaciendo el objetivo de foco métrico.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO el panel de indicadores
CUANDO el usuario selecciona un rango de fechas en el que no existen operaciones registradas
ENTONCES el sistema no presenta cálculos, mantiene el estado consistente y despliega un mensaje de alerta explícito indicando que no hay datos para procesar.

---

### 2.7. RF-007: Reoptimización Dinámica de Rutas

- **Descripción Atómica:** El sistema debe recalcular la ruta en curso desde el punto actual cuando un operador notifica un bloqueo vial o un pedido cancelado.

- **Prioridad:** Alta

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO una ruta en ejecución y un operador autorizado
CUANDO el usuario ingresa una alerta de calle bloqueada y solicita recalcular
ENTONCES el sistema procesa el evento y genera una nueva secuencia evitando el punto de conflicto correctamente.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un pedido cancelado de último minuto
CUANDO el usuario opta por remover la parada del recorrido y recalcular
ENTONCES el sistema completa la operación satisfaciendo el objetivo y reduciendo el tiempo restante de la ruta.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO un evento crítico de tráfico
CUANDO el usuario solicita la reoptimización pero se interrumpe la conexión al motor de cálculo
ENTONCES el sistema deniega la acción, mantiene el estado consistente y despliega un mensaje de error explícito sobre falla en la solicitud de recálculo.

---

### 2.8. RF-008: Generación de Reportes Operativos

- **Descripción Atómica:** El sistema debe generar un documento exportable con los detalles logísticos ejecutados cuando el usuario presiona la opción de descarga.

- **Prioridad:** Media

- **Criterios de Aceptación:**

#### Ruta Gold (Camino Ideal Principal)
DADO un usuario con rol administrativo
CUANDO el usuario solicita descargar el reporte de operación diaria
ENTONCES el sistema procesa la consulta a la base de datos y genera el archivo correctamente para su descarga.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO un requerimiento de auditoría
CUANDO el usuario opta por exportar el archivo en formato CSV en lugar de PDF
ENTONCES el sistema completa la operación satisfaciendo el objetivo con el formato alternativo.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO el módulo de reportes
CUANDO el usuario intenta descargar un reporte que excede el límite permitido de registros
ENTONCES el sistema deniega la descarga, mantiene el estado consistente y despliega un mensaje de error explícito instando a acotar el rango de búsqueda.
